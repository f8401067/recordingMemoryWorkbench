## 新增「对外 MCP 服务」（设置 → 数据与设备，在「开放 API」下方）

- 需求：对外提供 MCP 服务，工具含「上传录音（与设备/开放 API 上传等效）」「按日期输出 AI 纪要」，其余工具自行补充；Token 自动生成 + 可重置；能看到客户端与调用记录。
- 实现路线：**手写 MCP Streamable HTTP 协议（JSON-RPC 2.0），不用 mcp SDK 的服务端**。原因：项目里 `mcp>=1.9` 实际装的是 2.3.0，`FastMCP` 已改名 `MCPServer`、API 全变，挂 Starlette 子应用还要操心 lifespan；手写更可控，也便于逐请求鉴权和记日志。实测用官方 SDK v2 客户端 `streamable_http_client` + `ClientSession` 握手/列工具/调工具全部通过。
- 后端新增文件：
  - `app/migrations/versions/0013_mcp_service.py`：`mcp_service_tokens`（每账号一行，`mcps_` 前缀，enabled）、`mcp_service_sessions`（initialize 的 clientInfo + Mcp-Session-Id）、`mcp_service_logs`（最近 300 条）。
  - `app/services/audio_upload.py`：抽出「一次性上传音频 → 建录音/分片 → 排队转写 → 可选同步等待」共用链路；`routes/open.py` 的 `/api/open/transcribe` 已改为调它，MCP 的 `upload_recording` 也调它，保证两条上传效果一致。
  - `app/services/mcp_service.py`：Token 惰性生成/重置/停用、会话、日志脱敏（base64 只记字节数）、统计、`public_config`。
  - `app/services/mcp_tools.py`：9 个工具的 schema + 实现（upload_recording / get_daily_summary / list_recordings / get_recording / search_memory / list_summaries / get_action_items / generate_summary / get_service_status）。
  - `app/routes/mcp_service.py`：`/mcp`（POST/GET 405/DELETE）、兼容旧客户端的 `/sse` + `/messages`，以及 JWT 管理接口 `/api/mcp-service`（GET/PATCH）、`/reset-token`、`/logs`（GET/DELETE）。
- 前端新增 `web/src/pages/settings/McpServiceCard.tsx`，插入 `Settings.tsx` 的 data 标签「开放 API」与「硬件设备」之间；TABS hint、README 同步更新。
- 协议约定：`POST /mcp` 默认返回 `application/json`，若 Accept 只有 `text/event-stream` 则返回单条 SSE `message`；`initialize` 下发 `Mcp-Session-Id`；通知类请求回 202；工具错误放 `result.isError`；支持 batch 数组。鉴权接受 `Authorization: Bearer` / `X-MCP-Token` / `X-API-Key` / `?token=`。
- 验证：alembic 升到 0013；TestClient 全流程（握手/通知/列工具/9 个工具/未知工具/重置后旧 Token 401/停用 401）；官方 SDK 客户端真实 HTTP 连通；浏览器（ego-browser）确认卡片渲染、Token 遮罩、工具展开。自测录音与调用记录均已清理。
- 注意：数据库里账号已不是 `admin/admin123`（现有 `yangfan` / `test`）；验收时直接用 `app.security.create_token(uid, username)` 生成 JWT，不要猜密码。

## 找寻页工具列表改为「模型推荐子集」

- 需求：找寻的推荐工具列表只显示大模型认为可以使用的工具，不再把所有配置的工具都列出来。
- 定位：`Find.tsx` 底部固定栏原先用 `listChatTools()` 拉全量 chips（blinko 10 个全列）。
- 实现：
  - 新增 `app/services/mcp_recommend.py::recommend_chat_tools()`：把「问题 + 本次回答 + 全部工具（编号 t1..tN，名称/说明/参数）」交给 LLM，输出 `{"reason","tools":[{"ref","reason"}]}`；编号白名单、去重、最多 6 个；空回复 / 无效 JSON / 引擎异常时自动换另一台已启用的真实引擎重试，仍失败就返回空（宁可不推荐，不列全量）。
  - `services/finder.py::run_find()` 在回答生成后调用（复用已解析的 provider 与缓存工具清单），响应 `mcp` 新增 `recommendedTools` / `recommendBy` / `recommendReason` / `recommendNote`。不新增 HTTP 接口，推荐随消息一起进 sessionStorage，返回页面仍能看到。
  - 前端 `Find.tsx` 底部栏改为「本次推荐工具」，默认只渲染推荐项 + 内置检索 4；未提问时提示「问一句…」，模型判断无需工具时显示说明；保留「全部 N 个 / 只看推荐」折叠入口。`api.ts` 增 `McpRecommendedTool` 与 `FindResult.mcp` 字段。
- 坑：默认 LLM provider 是「智谱 · GLM」(glm-5.3-flash)，实测返回空串或无效 JSON；DeepSeek 正常。所以推荐里加了「必须解析出 tools 数组才算数」的换引擎重试，界面会显示「默认引擎无响应，已改用「DeepSeek 深度求索」判断」。这是既有配置问题，未改用户 provider 设置。
- 验证：10 个真实 blinko 工具 → 会议结论问句推荐 2 个（searchBlinko / upsertBlinko），天气问句推荐 1 个（webSearch），`run_find` 实测 10 → 1；tsc / build / compileall 通过；浏览器注入消息确认默认栏只有推荐项、点「全部 10 个」才展开全量。
- 重启 8787（最终 PID 34821），`web/dist` 入口 `index-D2sDa3qX.js`；README「对话里怎么用」与实现文件列表已更新。
- 启动方式坑：`scripts/start.sh` 有 `trap cleanup EXIT INT TERM HUP`，用「后台 Bash 任务」跑它时，任务被回收会连带优雅关闭服务（上次 exit 143 就是这个）。本轮试过 `open "启动 Recall.command"` 想交给独立 Terminal 托管，但沙箱内 `open` 没真正拉起脚本（端口一直空、日志无新行），最后仍用 `NO_OPEN=1 bash scripts/start.sh` 后台恢复。需要长期常驻时让用户自己双击 `启动 Recall.command`。
