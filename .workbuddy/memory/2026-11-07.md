## 日/周/月/年回忆改为层级式汇总（省 token / 省耗时）

- 背景：原先四类回忆各自按日期区间重新扫全部录音转写，年报会把全年原文重复跑（>16000 字走 map-reduce，notes 仍一次性塞给 LLM），慢且容易超上下文。
- 方案：`day` 读原始转写；`week/month/range` 读区间内各天日报 markdown；`year` 读 12 份月报 markdown。跨度 >366 天的区间回退到原文。
- 级联：`create_summary` 发现缺下级 → 父 `status='waiting'` → 后台 `checkChildren` 轮询 job（15s，只查库不调模型）幂等补齐下级（只对有录音的窗口建任务）→ 下级 ready 或超时 60min 后 `_kick_parent` 唤醒父。月报自身再按天级联，形成「年报 → 12 月报 → 各天日报」两级瀑布。
- 提示词按输入类型切换：`_user_prompt` 的 `inputDesc/materialLabel`、`build_system_prompt(hierarchical=)`、`build_chunk_prompt(hierarchical=)`；明确「下级回忆即本次原文依据」，禁止逐天复述，要求合并主线与转折。
- 前端：`waiting` 纳入 busy 与轮询，`Summary` 类型加 `waiting / childSummaries / childMissing`；Calendar 与 SummaryDetail 增加等待文案与「下级更新需重算本级」提示。
- 权衡：首次生成仍需一次性补齐下级；重新整理父级**不级联重算下级**，需按 日报 → 月报 → 年报 顺序各自刷新，改动才会传到最上层。层级是有损压缩。
- 改动文件：`server-py/app/services/{summarize,prompts,mcp_tools}.py`、`web/src/{lib/api.ts,pages/Calendar.tsx,pages/SummaryDetail.tsx}`、`README.md`。
- 验证：py_compile / compileall、npm typecheck、vite build 全通过；内存 mock 验证周报级联与年报两级瀑布（waiting → 补齐 → 唤醒 → 层级输入 → 重新整理零级联）。

## MCP「可发送纪要」工具支持人工覆盖

- 背景：`mcp_tools.capability` 原先只由 `analyze_tool()` 按 inputSchema 规则判定（**不是大模型**），设置页只读展示，刷新服务会整表重建覆盖；用户希望自己指定/取消。
- 数据：capability JSON 加 `manual: true` / `autoSendSummary` / `reason`。`_tool_capability()` 见 manual 直接返回，规则版本升级与 refresh 都不覆盖；`_save_tools()` 重建前先捞 manual，写回时保留，人工选的字段在新 schema 里不存在则回退当前自动推断值。
- 接口：`PATCH /api/mcp/servers/{id}/tools/{tool}/capability`，body `{sendSummary, bodyField?, titleField?, dateField?}` 或 `{reset:true}`；校验字段属于该工具的字符串参数，返回更新后的完整 McpServer。
- 前端：`McpTab.ToolRow` 每个工具加切换按钮、正文参数下拉、手动/自动徽标、恢复自动；`api.ts` 加 `setMcpToolCapability` 与类型字段。`SummaryMcpActions` 无需改，走 `/api/mcp/tools?scope=summary` 自动跟随。
- 注意：「总结推送（大模型按工具说明挑工具）」是另一条链路，不受人工覆盖影响。
- 验证：compileall / 路由注册 / 内存 mock（指定→刷新保留→排除→恢复自动）/ npm typecheck / vite build 全通过。
