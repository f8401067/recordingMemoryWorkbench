## MCP 工具新增时大模型自动生成建议入参（可人工修改）

- 背景：用户要求「后端的 MCP 工具新增时，要让大模型自己判断它的几个入参，自动匹配入参应该传什么，然后还可以手动修改」。范围经确认覆盖三个入口：调试面板（DebugPanel）、纪要一键发送（run-tool）、添加/刷新服务时预生成；LLM 只看工具 schema + 说明，不看纪要内容 / pushHint / 历史。
- 数据：迁移 `0014_mcp_tool_suggested_args.py` 给 `mcp_tools` 加 `suggested_args TEXT`、`suggested_at TEXT`（app 启动自动迁移，已验证列存在）。
- 后端：
  - 新增 `app/services/mcp_arg_suggest.py`：`suggest_args(user_id, tool, provider_id=None)` 只把工具名/说明/紧凑 schema 交给 LLM，引擎列表重试（默认网关无响应时自动换备用模型并提示）；`_normalize_suggestion` 白名单键 + 类型对齐 + 拆 `{"args":{}}`；`_rule_fallback` 只补必填；`validate_args` 白名单键 + `_coerce` 类型；`save_suggested/get_suggested` 读写模板；`prefetch_suggestions_bg` 守护线程后台预生成。
  - `mcp_servers._save_tools` INSERT 带 `suggested_args`；`refresh_server` 快照旧值按工具名恢复（人工模板不被刷新覆盖）；`_tools_of`/`summary_tools` 暴露 `suggestedArgs`；新增 `set_suggested_args`。
  - `mcp_dispatch.compose_summary_args(tool, summary, overrides=None)`：优先级 **用户 overrides > suggestedArgs > 纪要语义补全**；`_semantic_fixup` 只补 title/date 类字段且跳过用户改过的键；正文进识别出的正文字段（`text[:8000]`），`_text_slots` 兜底；最终按 schema 白名单过滤。`run_summary_tool` 走它，reason 改为「按工具建议参数 + 纪要正文自动填充」。
  - `routes/mcp.py`：`POST /api/mcp/run-tool` 可选 `args`（先 `validate_args`）；新增 `POST /api/mcp/run-tool-preview`、`POST /api/mcp/servers/{sid}/tools/{tool}/suggest-args`、`PATCH/GET /api/mcp/servers/{sid}/tools/{tool}/args`。
- 前端：
  - `api.ts`：`McpTool`/`McpSummaryTool` 加 `suggestedArgs`，`McpSummaryTool` 加 `schema`；`runMcpSummaryTool` body 加 `args`；新增 `previewMcpSummaryTool` / `suggestMcpToolArgs` / `setMcpToolArgs` / `getMcpToolArgs`。
  - `McpTab.DebugPanel`：初始与切换工具时预填列库建议参数（没有才用 sampleArgs 骨架）；工具行显示「AI 建议参数 N 项」徽标；参数区加「AI 生成」（现场重生成）与「存为模板」（写回库，刷新保留），原「重置为模板」保留。
  - `SummaryMcpActions`：点工具先弹「发送前确认」弹窗（`run-tool-preview` 合并结果，可编辑、可 AI 重新生成），确认后 `runMcpSummaryTool` 带 `args` 发送；文案「参数由大模型建议、发送前可改」。
- 踩坑：`validate_args` 原来只读 `inputSchema` 键，而 `summary_tools` 缓存链路把 schema 放在 `schema` 键，导致 overrides 被清空、用户改的 title 被语义补全覆盖——已改为两键都认，并验证 HTTP 全链路（preview → 改 title → run-tool 返回 saved 为改后的值，日志 source=summary）。
