## 转写队列集体失败（code=1）—— 真凶是 PYTHONPATH 注入的 sitecustomize

### 现象
11-01 01:45 起 197 个 transcribe 任务全挂，错误只有一句「本地 ASR 子进程意外退出（code=1）」，
每片 0.1~0.2 秒就退出；同一份音频手工跑 `python -m app.providers.local_asr_worker` 却完全正常。

### 定位
- 先给 `_LocalWorker._spawn` 加 `stderr=subprocess.PIPE` + 后台 pump，把子进程 stderr 末尾几行拼进
  RuntimeError。之前 `stderr` 是继承父进程的，子进程的崩溃输出混进服务日志，用户永远只看到 code=1。
- 拿到真实输出：`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {...targets: data/tmp/xxx.pcm}`，然后 exit(1)。
- 根因：**shell 环境里 `PYTHONPATH` 指向 `/Applications/WorkBuddy.app/.../cli/vendor/shim`**，里面有个
  `sitecustomize.py`（safe-delete 守卫），会给 `os.remove` 挂钩子。推理进程每次都要清理临时 pcm，
  被钩子拦下直接退出。服务本身带着这个钩子跑，所以日志里一直有 `[safe-delete]` 噪音。
  这个 shim 是 WorkBuddy/其他 agent 的 shell 注入的，用户自己在 Terminal 里 `npm run dev` 不受影响。

### 修复
1. `_spawn` 里 `env = {k:v for k,v in os.environ.items() if k != "PYTHONPATH"}`（worker 用 `-m` + cwd 就能找到 app 包）。
2. 启动服务一律用干净环境：`env -u PYTHONPATH -u NODE_OPTIONS .venv/bin/python -m app.main`。
3. 批量重排历史失败分片（157 + 70 个），复用原 job 行，跑完 **467/467 done，0 新失败**。
4. README「已知限制」后补一节「排障：本地 ASR 报子进程意外退出」写清这个坑。

### 注意
- 剩下 3 条 summary 仍是 failed，原因是那几条录音的 chunk.transcript 长度为 0（纯静音/噪音），
  `该录音还没有可用的转写内容` 是正确行为，不是 bug。
- **后台任务启动的服务会随会话清理被杀**；`nohup ... &` 在工具里也会被收走，用 `run_in_background` 托管，
  或者让用户自己 `npm run dev` 才稳。

## 15:30 修 `scripts/start.sh` 的退出逻辑（实测踩到的坑）

- **坑 1：前台 `tail -f "$LOG"` + trap**。收到信号时 bash 处理完 trap 会把「被中断的那条简单命令」**重新执行一遍**，
  结果就是脚本杀完服务又重新拉起 tail，卡住不退。改成 `tail -f &` + `TAIL_PID=$!` + `wait "$TAIL_PID"`。
- **坑 2：`kill` 后 `wait` 无上限**。本机 uvicorn 收 SIGTERM 有时不退（后台线程拖着），
  导致 cleanup 卡在 `wait` 里，脚本、python 全变孤儿。改成 TERM → 最多等 5 秒 → `kill -9` 兜底。
- cleanup 现在同时收 tail 和 python（两者都记 PID），只处理还活着的。实测 SIGINT 后 9 秒内
  `app.main` / `start.sh` / `tail` 三者全部消失，端口释放。
- 结论：**给服务收尾一律「先 TERM、限时、再 -9」**，别裸 `kill` + `wait`。

## 23:0x 新功能：PWR 短按暂停/恢复监听（实机验证通过）

需求：短按 PWR 暂停人声检测和录音，再按一下恢复。

实现（`app.c` 为主）：
- 新增状态 `ST_PAUSED`：麦克风/编解码器**整个关掉**（不是只屏蔽 VAD），屏幕显示
  `PAUSED / MIC + REC OFF / PWR: RESUME`；`ST_PAUSED` 主循环给 50ms 节拍不空转，
  也不参与深睡判断。
- PWR 键从 `pwr_key_held()` 改成事件化 `pwr_key_poll()`：
  短按（30ms~1.5s）= 暂停/恢复；按住 1.5s = 关机（关机后松手不会再补一个短按）。
  暂停/恢复只在 MONITOR/REC/PAUSED 生效，其它状态忽略。
- 正在录音时短按：先把当前这段正常收尾上传，再进暂停（`A.going_paused` 标志拦住
  `finish_session() → back_to_idle()` 重新开麦，避免多一轮开麦/关麦和墨水屏多刷一次）。
- `display.h` 新增 `SCR_PAUSED`，`epd_ui.c` / `lcd_ui.c` / `display.c` 三套驱动都补了画面。
- README「日常录音」「常驻监听」「按键总表」「关机」几处都更新了 PWR 说明；
  顺手把「待命时连点 3 下进配网」改成实际的“长按 3 秒”（三击根本没实现）。
- `clock.c` 的 PCF85063 probe 加了 3 次重试 + 30ms 间隔（真机上偶尔一次 probe 超时，
  之前会误报“没装 RTC”）。

实机验证（串口日志）：
- 录音中短按 → `spool: saved …3580ms` → `状态 3 -> 4` → `短按 PWR：暂停监听/录音`；
  暂停期间无新片段、无 VAD 触发。
- 再短按 → `状态 4 -> 3` → `短按 PWR：恢复监听` → 1.5s 后 VAD 重新触发录音（seq=698）。
- 编译 0 警告，`0x14fed0 / 0x1c0000`（25% 余量）。
- 注意：暂停期间后台补传照常跑（本次暂停 11 秒里把 29 个积压分片传完了）。

## 23:2x 定时补传 + VAD 误触发修复（实机验证）

### 新增：每 4 小时定时补传
- Kconfig `RECALL_PERIODIC_UPLOAD_S`（默认 14400 秒 = 4 小时，0=关闭），
  `sdkconfig.defaults.esp32s3` 里也写死了 14400。
- `app.c` 上传任务：`s_last_pass_ms` 记住上次**成功**上传轮次（开机初始化为启动时刻），
  超过间隔且有积压文件 → 主动开 WiFi 传一次，并置 `close_wanted` 让服务端收尾出转写/纪要；
  没文件时早退分支直接跳过，不会白开射频。成功一轮后重置计时。
- 实机用 120 秒验证：`[upload] 定时补传（间隔 120 秒，2 个文件待传）` → 2 片上传 OK →
  `收尾 HTTP 200` → WiFi 关闭。正式固件已改回 14400。

### 修 bug：没人说话也一直录音
- 真机日志抓到 VAD 在 `rms=14~45`（几乎静音）时连续判"人声"，
  触发后每 30~60 秒就开录一次，还会存下 2~8 秒的垃圾片段。
- 根因：ESP-SR（WebRTC）VAD 只看频谱特征，安静底噪也能偶发误判；原代码没有任何能量门槛。
- 修复：`vad.c` 增加**自适应噪声底 + 能量闸门**：
  `above = VAD说人声 && rms >= max(VAD_RMS_ABS_MIN, noise_rms*VAD_NOISE_FACTOR + VAD_NOISE_MARGIN)`
  - 噪声底：更安静时快速降（0.8/0.2），VAD 判静音时极慢上浮（0.995/0.005），说话帧不动；
  - 参数在 `app_config.h`：`VAD_RMS_ABS_MIN=150`、`VAD_NOISE_FACTOR=2.5`、`VAD_NOISE_MARGIN=50`；
  - `vad_t` 新增 `noise_rms` / `last_gate`（日志里会打）。
- 实机验证：安静 3 分钟**零误触发**；Mac 播测试语音 → `rms=3427 level=87 noise=14 gate=150`
  正常开录；残余短噪声（rms=819）被"3 秒内人声<500ms"兜底逻辑丢弃。
- README 已更新：上传触发表加"定时补传"，配置表加 `RECALL_PERIODIC_UPLOAD_S`，
  旧的 `VAD_TRIGGER_RATIO`/`VAD_MIN_RMS` 文档换成新参数。
- 定时补传失败处理：如果这一轮是「定时」触发（非双击/非存储满）且仍有积压文件，
  失败后把 `s_last_pass_ms` 推到当前时刻——下一轮再等 4 小时，避免没 WiFi 时
  30 分钟一次的退避反复连网耗电。手动触发/存储将满仍按退避重试。

## 23:3x 按原理图补全 TF 卡（SDMMC 1-bit）并实机跑通

用户提供了微雪官方原理图 `ESP32-S3-Touch-ePaper-1.54-Schematic.pdf`，
用 `pdftotext -layout` 提取网络名 + 官方例程 04_SD_Card 的 `sdcard_bsp.c` 交叉核对，
确认整板引脚（与现有 board.h 基本一致）：

| 功能 | GPIO 结论 |
| --- | --- |
| TF 卡 | **SDMMC 1-bit：CLK=39 / CMD=41 / D0=40**；原理图 `SD_CS` 是 NC（没有 SPI 的 CS！） |
| 墨水屏 | BUSY=8 RST=9 D/C=10 CS=11 SCLK=12 SDI=13（与 board.h 一致） |
| I2S/ES8311 | MCLK=14 SCLK=15 ASDOUT=16 LRCK=38 DSDIN=45；I2C SDA=47 SCL=48 |
| 按键 | BOOT=GPIO0，PWR(BAT_KEY)=GPIO18；LED=GPIO3；电池自锁 BAT_Control=GPIO17 |
| 功放 | PA_EN=GPIO42（Q6 P-MOS 控 PAVCC）、PA_CTRL=GPIO46（NS4150B CTRL） |
| 触摸 | EPD_TP_INT=GPIO21、EPD_TP_RST=GPIO7、I2C 共用 47/48（本固件暂不用） |

### 改动
- `spool.c` 的 `mount_sd()` 从 **SPI3 + sdspi** 改成 **SDMMC 1-bit**
  （`SDMMC_HOST_DEFAULT()` + `width=1` + clk/cmd/d0）；`esp_vfs_fat_sdmmc_mount`。
  原因：这块板 TF 座的 CS/DAT3 是 NC，SPI 模式根本没法片选。
- Kconfig 引脚项改名：`RECALL_SD_CLK / CMD / D0`（删掉 MOSI/MISO/CS），
  `app_config.h` 同步成 `PIN_SD_CLK/CMD/D0`；`CMakeLists` 加 `esp_driver_sdmmc`。
- **默认启用**：`sdkconfig.defaults.esp32s3` 写死 `RECALL_SD_ENABLE=y` + 39/41/40。
- 坑：FATFS 的 `statvfs()` 在 IDF v6 返回全 0 → 日志出现「可用 0 KB」，
  而 `gc_if_needed()` 看到 free=0 会每 15 秒删一个最老录音（差点变成"边录边删"）。
  改用 `esp_vfs_fat_info()` 取真实 total/free。
- README「TF 卡」章节按原理图重写：SDMMC 1-bit 三根线表格 + 官方例程佐证。
