# 忆录录音笔 · ESP32 固件

长按录音 → 人声检测 → Opus 压缩 → **先存本地 Flash** → 智能判断要不要传 → 上传服务端 → 自动转写 + 纪要。

配套服务端接口见项目根 `README.md` 的「硬件设备接入」一节，本固件就是那套协议的完整实现。

```
┌──────────────┐   I2S 16kHz    ┌──────────┐  20ms 帧   ┌────────┐
│ INMP441 数字麦│ ─────────────▶ │   VAD    │ ────────▶ │  Opus  │ 12kbps
└──────────────┘                └──────────┘  有人声才编 │ 编码器  │
                                                       └────┬───┘
                                                            │ Ogg 封装
                                      ┌─────────────────────▼──────────┐
                                      │  LittleFS /spool/*.ogg  (断电不丢) │
                                      └─────────────────────┬──────────┘
                                                      停止录音 │
                                    有效语音 ≥3s ? ──否──▶ 直接删除
                                            │是
                                            ▼
                              WiFi → POST /api/open/ingest → 转写
                                            │
                              POST /api/open/ingest/close → 纪要
```

## 1. C3 还是 S3

| | ESP32-C3 | ESP32-S3 |
| --- | --- | --- |
| 内核 | 单核 RISC-V 160MHz | 双核 XTensa LX7 240MHz |
| PSRAM | 无（400KB SRAM） | 常见 8MB Octal/Quad |
| 深睡电流（芯片手册） | 5µA | 7µA |
| 空闲（关 WiFi，80MHz） | ~15mA | ~25mA |
| 跑 12kbps Opus 的 CPU 占用 | ~25–30% / 160MHz | ~15% / 160MHz |
| 屏幕/外设余量 | GPIO 不够时很紧 | 富余，可上 TFT |
| 单价 | 最低 | 略高 |

**结论：当前只做 S3。C3 先放着，代码路径保留但不再作为验证重点。**

> ⚠️ **项目当前口径（2026-10）**：优先把 `esp32s3` 这条路走通、上真机、调参数。
> C3 的编译分支和分区表都还在（`idf.py set-target esp32c3` 仍能编过），
> 但不再跟着一起验证，等 S3 定型后再回头补。下文凡是标「C3」的内容都按**待启用**看待。

- S3：双核 LX7 240MHz + PSRAM，编码、VAD、LittleFS 写盘、HTTP 同时在跑也不喘；想加 TFT 屏、放大录音缓冲都随意。**本仓库默认 target 就是 `esp32s3`**，接线/调参/排错都以它为准。
- C3（待启用）：单核跑满也够（12kbps 下 Opus 约 25–30% CPU），但 RAM 只有 400KB，**别开 `RECALL_AUTO_SESSION` 之外的花哨功能**，也别指望上彩屏。深睡电流反而比 S3 更低，适合以后做极简款。

S3 固件已编译通过（见第 11 节）；C3 最后一次编译也通过，但之后的新改动不保证同步验证。

## 2. 省电：四个工作区

设备不是"一直录"，而是四档功耗来回切：

| 状态 | 触发 | 电流（估算） | 在干什么 |
| --- | --- | --- | --- |
| **深睡** | 待命闲置 5 分钟 | **10–60µA**（芯片 5–7µA + LDO 静态电流） | 只留按键唤醒，麦克风断电 |
| **待命** | 开机 / 唤醒后 | 12–18mA | 麦克风关，只轮询按键，屏幕 8Hz 刷新 |
| **暂停** | 监听/录音中短按 PWR | **<0.3mA** | 墨水屏断电（画面保留）、麦克风与 codec 断电、WiFi 关闭、80MHz + 自动 light sleep；暂停超过 2 小时自动深睡，按 PWR 唤醒 |
| **录音** | 长按开始后 | 25–35mA | I2S 采样 + VAD + Opus + 写 Flash，WiFi 关闭 |
| **上传** | 存储快满 / 双击 / 开机补传 | 100–150mA（几秒~几十秒） | WiFi 发射，传完立刻关射频；一天可能只开一次 |

省电的六个具体手段，都在代码里：

1. **闲置即深睡**：`RECALL_IDLE_SLEEP_S`（默认 300 秒）后 `esp_deep_sleep_start()`，按键 `ext1`/GPIO 唤醒。按下去就醒，顺手接着算长按，不用按两次。
2. **麦克风可断电**：`PIN_MIC_PWR_EN` 接个 MOSFET，不开麦时麦克风彻底没电（INMP441 常开约 1.2mA，跟深睡电流比是数量级的差）。没接就是空操作。
3. **VAD 决定写不写**：没人在说话时**不进编码器、不写 Flash**。会议里 50%+ 时间是静音，这一条直接省掉一半 Flash 写入和一半文件体积。
4. **动态调频 + 暂停休眠**：`esp_pm` 配 80–160MHz，平时 80MHz 跑，编码时自动拉满；**暂停时**麦克风已断电，再切到 80MHz + 自动 light sleep，整机进入亚毫安级。
5. **射频按需开**：只在"存储快满 / 双击 / 开机补传"这三种情况下才开 WiFi，平时录多久都不碰射频；连上后立刻 `WIFI_PS_MIN_MODEM`，传完 `esp_wifi_stop()`。**连不上也必须立刻关射频**，否则会卡在自动重连循环里持续耗电。
6. **少写 Flash**：每 15 秒落一个文件，不是每帧都 fsync；LittleFS 本身是掉电安全的。

### 为什么平时不用 light sleep

I2S 靠 APB 时钟采样，进 light sleep 时钟就停了，麦克风会断音。所以监听/录音期间**宁可 80MHz 空转也不睡**——真省电靠的是"没活干就深睡"，不是"半梦半醒"。

暂停状态是唯一例外：麦克风和 codec 已经断电，没有外设在占 PM 锁，所以这时会打开自动 light sleep，等下一段 20ms 的空闲就睡，按键唤醒后再恢复 160MHz 回监听。插着 USB 调试时（`usb_serial_jtag_is_connected()`）会自动跳过 light sleep，避免串口掉枚举。

### 续航估算（1000mAh 电池）

| 用法 | 平均电流 | 续航 |
| --- | --- | --- |
| 连续录音（不放静音） | ~30mA | **约 33 小时** |
| 每天录 2 小时，其余深睡 | ~2.6mA | **约 16 天** |
| 只待机不录音（不深睡） | ~15mA | 约 66 小时 |
| 只待机（深睡） | ~50µA | 约 2 年（受电池自放电限制） |

> 电流是按数据手册 + 常见模块实测口径估的，不是这块板子的实测值。板载 LDO 的静态电流（常见 20–50µA）经常比芯片深睡电流还大，做低功耗选 LDO 时留意。

### 想再省一个数量级？

真正的"永远在线、0.1mA 级"需要 **S3 的 ULP-RISC-V 协处理器 + 模拟麦**：主核深睡，ULP 用 ADC 以 100Hz 采样能量，超过阈值才唤醒主核。本固件没做（C3 没有 ULP，写了两套代码维护成本高），但状态机已经把入口留好了——`RECALL_AUTO_SESSION` 打开后，"检测到人声就自动开录"的路径已经通了。

## 3. 接线

### 正点原子 ATK-DNESP32S3 BOX0（当前默认，menuconfig 里的「开发板」选它）

整机方案，什么都不用接。引脚全部写死在 `app_config.h` 的
`CONFIG_RECALL_BOARD_BOX0` 分支，来源是小智固件的同款板级
（`xiaozhi-esp32/boards/alientek/atk-dnesp32s3-box0/config.h`）：

| 模块 | 引脚 |
| --- | --- |
| 屏幕 | ST7789 240x240 方屏：SCLK=39 / MOSI=40 / CS=41 / DC=38，背光=GPIO42 |
| 音频 | ES8311（采集+播放一颗搞定）：BCLK=5 / WS=10 / DIN=6 / DOUT=9，不用 MCLK |
| 麦克风 | 板载模拟咪头，走 ES8311 的 ADC，增益 30dB |
| 按键 | R=GPIO0（BOOT 键，长按录音）、M=GPIO4、L=GPIO3 |
| LED | GPIO13 板载蓝灯（高电平点亮） |
| 电源 | SYS_POW=2（上电自锁）、CODEC_PWR=14（ES8311 供电）、PA=21（功放） |
| I2C | SDA=11 / SCL=12（触摸屏 CHSC5432 也挂在这条总线上，固件暂不用） |

上电固件会自动拉高 SYS_POW 和 CODEC_PWR，电池供电也不会松手断电。

### ESP32-S3 最小系统板（自己接线）

| 模块 | 引脚 | ESP32-S3 |
| --- | --- | --- |
| INMP441 / ICS-43434 | VDD | 3V3 |
| | GND | GND |
| | L/R | GND（选左声道） |
| | SCK | GPIO4 |
| | WS | GPIO5 |
| | SD | GPIO6 |
| 按键（轻触） | 一端 | GPIO14 |
| | 另一端 | GND（内部上拉） |
| LED | 阳极串 1kΩ | GPIO15 |
| 蜂鸣器（无源） | + | GPIO16（建议过三极管） |
| SSD1306 OLED | SDA / SCL | GPIO8 / GPIO9（3V3、地址 0x3C） |
| ST7735 TFT 160x80 | SCLK / MOSI / CS / DC / RST | GPIO12 / 11 / 10 / 13 / 21 |

### ESP32-C3（4MB Flash 版，待启用）

| 模块 | 引脚 | ESP32-C3 |
| --- | --- | --- |
| INMP441 | SCK / WS / SD | GPIO4 / GPIO5 / GPIO6 |
| 按键 | | GPIO3 → GND |
| LED | | GPIO10 |
| 蜂鸣器 | | GPIO7 |
| SSD1306 | SDA / SCL | GPIO0 / GPIO1 |

注意事项：

- **麦克风一定接 3.3V**，接 5V 会烧。
- `GPIO2/8/9` 在 C3 上是 strapping 脚，别拿来接按键。
- 板载 LED 多数是低电平点亮，代码里 `LED_ACTIVE_LOW=1`；外接 LED 记得改成 0。
- 想要更省电：麦克风 VDD 串一个 P-MOS，栅极接 `PIN_MIC_PWR_EN`（S3 默认 GPIO7，改 `app_config.h` 即可）。

## 4. 编译与烧录

需要 ESP-IDF **v5.3 及以上**（本仓库用 v6.1 验证）。

```bash
cd esp32

# 1) 选芯片（当前只跟 S3，C3 先放着）
idf.py set-target esp32s3

# 2) 填服务器地址（出厂默认值）和可选的 WiFi
idf.py menuconfig
#   → 忆录录音笔 → 网络与账号：服务端地址 / 设备名
#        WiFi 可以留空，开机后用手机现场配网；服务端地址也能在配网页面上改（见第 5 节）
#   → 忆录录音笔 → 硬件：屏幕类型（无屏 / SSD1306 / ST7735）

# 3) 编译烧录
idf.py build
idf.py -p /dev/tty.usbmodem* flash monitor
```

分区表按 Flash 容量选（`sdkconfig.defaults.esp32c3` 里改）：

| Flash | 分区表文件 | 暂存区 | 能存多少纯语音 |
| --- | --- | --- | --- |
| 4MB | `partitions_4mb.csv` | 1.4MB | ~15 分钟 |
| 8MB | `partitions_8mb.csv`（默认） | 5MB | ~55 分钟 |
| 16MB | `partitions_16mb.csv` | 12MB | ~2.2 小时 |

> 12kbps 下 1 分钟约 90KB。会议里通常只有 40–50% 时间在说话，加上 VAD 跳过静音，实际能存的时长大约是上表的 2 倍。

### TF 卡（可选，但出门一整天基本是必须的）

片内 5MB 只够存两小时出头的纯语音。**出门一整天没法上传时，这个容量是不够的**——所以接了卡就用卡：

| 介质 | 能存纯语音 | 折算真实时间 | 说明 |
| --- | --- | --- | --- |
| 片内 Flash（8MB 板） | 55 分钟 | 约 2.2 小时 | 默认，什么都不用配 |
| TF 卡 8GB | ~118 小时 | 几个月 | 够用 |
| TF 卡 32GB | ~473 小时 | 半年以上 | 随便存 |

**没插卡、卡不是 FAT32、引脚填错——都不会影响录音**，固件会自动退回片内 Flash，只在日志里打一行说明。开机页脚会显示当前用的是哪个：

```
READY                      ← 用 TF 卡
──────────────
HOLD 0.7S
SD 12000KB
PAIRED

READY                      ← 用片内 Flash
──────────────
HOLD 0.7S
FLASH 4800KB
PAIRED
```

打开方式：默认已经打开（`RECALL_SD_ENABLE=y` + 三个引脚都填好了）。要改就：

```bash
idf.py menuconfig
#   忆录录音笔 → 硬件 → 用 TF 卡存录音 / TF 卡 CLK / CMD / D0
```

**引脚来源（微雪 ESP32-S3-Touch-ePaper-1.54 原理图实测）**：这块板的 TF 座是 **SDMMC 1-bit**，不是 SPI：

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| TF_CLK | **GPIO39** | 时钟 |
| TF_CMD | **GPIO41** | 命令线（SPI 模式的 MOSI） |
| TF_D0 | **GPIO40** | 数据线（SPI 模式的 MISO） |
| TF_CS | — | 原理图上 `SD_CS` 是 NC，SD 模式不需要 |

所以代码里用的是 `SDMMC_HOST_DEFAULT()` + `width=1`，**不能用 `sdspi`**（没有 CS 可接）。官方例程 `02_Example/ESP-IDF/V2/04_SD_Card` 的 `sdcard_bsp.c` 同样是 `D0=40 / CLK=39 / CMD=41`。

几点实现细节：

- 走 **SPI3**，和屏幕的 SPI2 分开，互不干扰。
- 卡必须格式化成 **FAT32**；`format_if_mount_failed = false`，不会去格式化别人的卡。
- 不支持热插拔：插拔卡之后重启一次（LittleFS/FAT 都怕写一半被拔）。
- 挂载点 `/sdcard`，片内是 `/spool`，上层逻辑完全不用管是哪个。

## 5. 联网：设备怎么上网

只支持 **2.4GHz**（ESP32 没有 5G 射频）。WiFi 凭据和**服务端地址**都存在 NVS 里，优先级 **NVS > menuconfig**，换固件不会丢。

三种路子，按场景选：

### 方式一：编译期写死（自己用最省事）

```bash
idf.py menuconfig
#   忆录录音笔 → 网络与账号 → WiFi 名称 / WiFi 密码 / 服务端地址
```

烧一批同款设备、都是同一个 WiFi + 同一个服务器时这样最省事；缺点是换 WiFi 或换服务器要重新烧。

### 方式二：手机现场配网（推荐，送人 / 出厂默认）

NVS 里没有 WiFi 凭据时，设备开机自动进配网：

1. 手机 WiFi 列表里连 **`Recall-123456`**（后 6 位是设备编号，默认是开放热点）
2. 自动弹出或手动打开 **http://192.168.4.1**
3. 页面上先列出**已经存过的网络**（★ 是首选），下面可以再添一个：
   - **WiFi 名称**：自动扫描，列出 2.4G 热点 + 信号强度 + 🔒 标记，下拉选一个
   - **密码**：没有密码留空
   - **服务器地址**：自动填当前生效的值（`http://192.168.1.10:8787` 之类），改成电脑现在的局域网 IP 就行
4. 点「保存并重启」→ 设备把新网络**追加**进列表（最多 4 组）→ 自动 `esp_restart()`

**多网络是这台设备出门能用的关键**：家里、公司、手机热点各存一次，之后走到哪都自动挑那个在范围内的连，不需要重新配网。

无屏设备也能用：进配网时 LED 常亮 + 一声「嘀」，配网过程中网页上就能看到设备编号，不用听蜂鸣器念。

想给热点加密码（防隔壁邻居顺手改）：`menuconfig → 网络与账号 → 配网热点密码`，至少 8 位，留空即开放。

> 服务端地址会做基本校验（必须以 `http://` 或 `https://` 开头），结尾斜杠会自动去掉。
> 填错了不用慌：连不上就一直 `PAIR`，再连点 3 下进配网改回来就行，录音不会丢（都在 Flash 里）。

### 方式三：待命时连点 3 下重新配网

搬家 / 换路由器 / 改密码 / 换服务器 IP 时都不用重新烧固件：

> **`READY` 状态下 1.5 秒内连点 3 下按键** → 进配网热点，其余操作完全不变。

录音中不响应连点（避免手抖），只有 `READY` 和 `PAIR` 两个状态有效。

### 连多个 WiFi 时的挑选顺序

不是按存的顺序死板重试，那样在"家里存的网络跑到公司"会白等 2×6 秒：

```
扫一次 AP 列表（约 1.5 秒）
  → 已保存的网络里，此刻能扫到的排前面，按信号强弱排
  → 扫不到的排在后面兜底
  → 逐个试，每个最多 6 秒拿到 IP
  → 连上就把它提到列表首位（下次优先）
```

扫描只在**存了 2 个以上**网络时才做；只存一个就直接连，不多花这 1.5 秒。

### 重置：清 WiFi 和彻底清空是两件事

| 操作 | 清掉什么 | 保留什么 | 什么时候用 |
| --- | --- | --- | --- |
| **长按 3 秒**（物理按键） | 全部 WiFi 列表 | **配对 token 保留** | 换路由器 / 搬家 / 密码改了 |
| 配网页底部「恢复出厂设置」 | WiFi + 配对 token | 录音文件不动 | 送人 / 换服务器 / 换账号 |

两种都会重启进配网，重启后**不需要去服务端做任何操作**：

- 只清 WiFi → 配好网直接用原 token 上传，服务端毫发无损
- 恢复出厂 → 设备用同一个编号重新轮询 `/api/open/pair`，服务端认得这台设备就**自动把 token 发回来**

### 细节与边界

| 项 | 值 |
| --- | --- |
| 热点名 | `Recall-<设备编号>`，如 `Recall-903471` |
| 配网地址 | `http://192.168.4.1`（Android 可能提示"无互联网"，选「保持连接」） |
| 可配项 | WiFi（可存 4 组）、服务端地址 |
| 界面接口 | `GET /`（页面）、`GET /cfg`（回填配置 + 已存列表）、`GET /scan`（扫热点）、`POST /save`、`POST /del`、`POST /factory` |
| 等待时长 | `RECALL_PROV_TIMEOUT_S`，默认 180 秒，超时自动关热点 |
| 没配 WiFi 会怎样 | 开 3 轮热点（约 9 分钟），之后进 `PAIR`，2 分钟没人管就深睡；按键唤醒会重新进配网 |
| 清空配置 | 配网页「恢复出厂」，或 `idf.py erase-flash`（连 token 一起清） |

`RECALL_SERVER_URL` 现在只是**出厂默认值**：全新设备 / 刚 erase 过的设备用它，一旦在配网页面上改过，就以 NVS 里的为准。menuconfig 里填的 WiFi 同理，只作为"列表为空时"的最后兜底。

## 6. 使用流程

### 首次配对

1. 上电。如果还没配过 WiFi，会先进配网热点（见第 5 节），配完自动重启。
2. 有屏：屏幕显示 `PAIR` + 6 位编号；无屏：蜂鸣器逐位播报（0 用一声长音表示）。
3. 设备每 3 秒带编号轮询 `/api/open/pair`：
   - **单账号服务器**（自己家这种）：直接自动建档并下发 token，屏幕几秒后转 `READY`，**不用去后台点任何东西**
   - **多账号服务器**：编号进入"待配对"列表，去「设置 → 硬件设备 → 添加设备」输这串数字即可
4. 设备取回 token 存进 NVS，蜂鸣器「嘀嘀嘀」表示成功，屏幕转 `READY`。

编号由 MAC 打散算出，永远不变。所以**设备被恢复出厂、服务端换过库、token 被换发**都不会卡死：上传收到 401 → 清 token → 重新轮询 → 自动拿回（或自动建档）。整个过程不需要人工去服务端"重置 token"。

### 日常录音

| 操作 | 设备反应（有屏） | 设备反应（无屏） |
| --- | --- | --- |
| **双击**（监听中） | 立刻把攒着的录音传上去 | 两声短促「嘀嘀」，LED 慢闪 |
| 录音中**双击** | 结束这一段，回监听（不立刻上传） | 一声长「嘀——」 |
| **长按 0.7 秒** | 停止并回到待机（关麦） | 一声长「嘀——」，LED 熄灭 |
| 待机中**双击** | 回到常驻监听 | 两声短促「嘀嘀」 |
| 上传成功 | `SENT` + 本次大小 | 三声「嘀嘀嘀」 |
| 没录到人声 | `SKIP / NO VOICE`（本地文件直接删） | 一声长低音后 LED 熄灭 |
| 出错 | `ERR` + 原因 | 一声很长的低音 |
| 监听/录音中**短按 PWR** | **暂停**：麦克风断电、不再检测人声也不录音，屏幕 `PAUSED / MIC + REC OFF`，绿 LED 转**微亮**（约 8%，PWM）；再短按一下恢复 `LISTENING` | 一声长「嘀——」，LED 微亮 |
| 待命时**长按 3 秒** | 清 WiFi 列表并重启进配网热点，屏幕 `CONNECT TO / RECALL-XXXXXX / 192.168.4.1` | LED 常亮 + 一声「嘀」 |

### 常驻监听（一整天开着用这个）

`RECALL_ALWAYS_ON=y` 时设备开机就守麦，不用按任何键：

| 场景 | 设备行为 |
| --- | --- |
| 安静 | 屏幕 `LISTENING / SPEAK ANYTIME`，麦克风开着做 VAD，不写 Flash、不刷屏 |
| 有人说话 | 自动开录（屏幕切 `REC` 并冻结画面，计时不再刷新） |
| 说完静音 `RECALL_SILENCE_SPLIT_MS`（默认 30 秒） | 收尾、`SEND` 上传、删本地文件、回到 `LISTENING` |
| 说完 < 1 秒 | 直接丢（`RECALL_MIN_VOICED_MS`） |
| 想立刻结束当前这段 | **双击**录音键（结束这段回监听） |
| 想暂停一整天监听、省电 | **长按 0.7 秒** → 回待机；双击再回来 |
| 开会 / 中途不想被录 | **短按 PWR** → 暂停（麦克风彻底断电，屏幕刷一次 `PAUSED` 后也断电、画面保留）；**再短按一下**恢复监听。正在录音时短按会先把当前这段正常收尾上传，再进暂停。暂停中**双击 BOOT** 仍然可以手动补传，只是屏幕断电了看不到 `SENDING / SENT` 提示。暂停状态下绿 LED 是**微亮**（PWM 约 8%），表示"还开着但没在录"。暂停超过 **2 小时**会自动深睡，按 PWR 唤醒（会走一次开机流程重新进监听） |
| 按键总表 | 双击=上传（监听中）/ 结束这段（录音中），长按 0.7s=回待机，长按 3s=清 WiFi 列表（重启后自动进配网），**PWR 短按=暂停/恢复**，PWR 按住 1.5s=关机 |
| 换网络 / 搬家 | **长按 BOOT 键 3 秒**：只清 WiFi 列表，配对 token 保留 → 重启进配网，配完直接用原 token 上传 |
| 送人 / 换服务器 | 配网页底部「恢复出厂设置」：清 WiFi + token → 重启后自动向服务端重新认领，**不用去后台重置 token** |
| 关机 | **长按 PWR 键 1.5 秒**：屏幕先刷成黑底大白字 `OFF`，再断电池自锁（断电后画面保留）。注意区分：**短按 PWR 是暂停，按住 1.5 秒才是关机** |

代价：这个模式不深睡（深睡就没法守麦了），常驻约 18–25mA；1000mAh 电池大约撑 1.5–2 天。屏幕在监听/录音时不刷新，也是为省电——墨水屏刷一次要几百毫秒。

### 上传：攒着，快满了才传

录音和上传是两条并行的事：主循环只管录音/界面，**上传跑在 CPU1 的独立任务里**，所以上传期间麦克风照常在听。

**什么时候才会真的联网**（这是省电的关键）：

| 触发 | 说明 |
| --- | --- |
| **存储快满了** | 剩余空间低于总容量的 20%（上限 32MB、下限 512KB）→ 趁没在录音的时候自动传一次 |
| **双击按键** | 不管攒了多少，立刻传，传完顺便让服务端出纪要 |
| **开机时** | 上次没传完的补传一次（多半是"出门攒了一天，回家重新开机"） |
| **定时补传** | 距上次成功上传超过 `RECALL_PERIODIC_UPLOAD_S`（默认 **4 小时**）且有积压文件 → 开一次 WiFi 传完，并让服务端收尾出转写/纪要。设 0 关闭。注意：定时这一轮如果连不上 WiFi，下次要再等一个周期，不会每 30 分钟反复连网耗电 |
| 其他时候 | **完全不碰射频**，文件躺在卡里，只有麦克风和 VAD 在耗电 |

早期版本是"录完就传"，一天几十上百次开关 WiFi，电池全耗在射频上。现在改成按容量触发，出门一整天可以一次都不联网。

- 每 15 秒封一个分片，封口后随时可以传；**录音进行中不会传**，等这段收尾。
- 服务端会话只在**没有正在录音**的时候收尾（`/ingest/close`），否则会把一次连续录音切成好几条记录。
- 传输失败按 30 → 60 → 120 …→ 1800 秒退避重试，不会每半分钟醒一次耗电。
- 屏上显示 `SENDING 3/8` / `N PENDING` / `SENT` / `SEND FAIL`；空间不足丢最老文件时显示 `STORAGE LOW`。
- 重试全部失败也不会丢文件，它们留着等下一次；只有空间跌破 48KB 才会删最老的。

### 智能判断：传还是不传

- 一次录音里**真正有人说话**的累计时长 < `RECALL_MIN_VOICED_MS`（默认 3 秒）→ 判定"这次没录到东西"，本地文件删除，不联网。
- 够长 → 上传。上传成功立刻删本地文件；失败则**留在 Flash**，下次开机或 15 分钟后定时唤醒重试。
- 服务端按**录制时间**归并会话：相邻两片间隔小于 90 秒会自动合成一条记录（阈值可在后台按设备调）。带 `recordedAt` 时用录制时间判断，老固件不带才退回到达时间——这样回家补传不会被并成一整天。

## 8. 音频方案

| 方案 | 码率 | 1 分钟 | 说明 |
| --- | --- | --- | --- |
| PCM/WAV 16kHz 16bit | 256kbps | 1.9MB | 原始，Flash 撑不住 |
| IMA-ADPCM | 64kbps | 480KB | 免依赖，但 4 倍于 Opus |
| **Opus 12kbps VOIP** | **12kbps** | **90KB** | 专为语音设计，识别准确率几乎无损 |

选 Opus 的理由：它是为**语音**设计的（SILK 层），12kbps 下的可懂度远超同码率的 MP3/AAC；服务端 ffmpeg 直接解，转写链路一行不用改。

链路细节：

- 采样 16kHz / 16bit / 单声道，I2S 一次读 20ms（320 采样）。
- VAD 判为静音就不进编码器——既省 Flash，也让识别更干净（没有大段静音）。
- 真机上 WebRTC VAD 会把 RMS≈15~50 的底噪偶尔判成人声，所以现在又叠了一道**能量闸门**：
  `VAD 说人声` 且 `RMS ≥ max(150, 噪声底×2.5+50)` 才算触发，安静环境不会自己开录。
- 编码器：乐鑫官方 `esp_audio_codec` 的 OPUS，帧长 20ms，VOIP 模式，复杂度默认 2（C3 建议 1–2）。
- 封装：自己写的极简 Ogg 封装（`ogg_mux.c`，~180 行）。Ogg 页序号单调递增、CRC32 按 Ogg 规范（poly 0x04C11DB7）、granule 按 48kHz 计。
- 服务端：`Content-Type: audio/ogg` → 存盘 → ffmpeg 转 16k PCM → ASR → 纪要。

### 这个封装是验证过的

```bash
cd esp32/tools
ffmpeg -f lavfi -i "sine=frequency=440:duration=6" -ar 16000 -ac 1 \
       -c:a libopus -b:a 12k -frame_duration 20 /tmp/ref.ogg
python3 ogg_roundtrip.py /tmp/ref.ogg /tmp/pkts.bin     # 抽出真实 Opus 包
cc -O2 -I../main test_ogg_mux.c ../main/ogg_mux.c -o /tmp/test_ogg_mux
/tmp/test_ogg_mux /tmp/pkts.bin /tmp/mine.ogg           # 用固件同一份代码重封
ffprobe /tmp/mine.ogg                                   # duration=6.0265, codec=opus
```

用参考文件重新封装后，解码出的 PCM 与原件**相关系数 1.0000**（只多 216 个采样点，是尾部补帧）。

## 9. 和服务端的接口对照

| 时机 | 请求 | 用途 |
| --- | --- | --- |
| 未配对，每 3 秒 | `GET /api/open/pair?code=903471&name=...&firmware=1.0.0` | 已知设备直接下发 token；单账号服务器上全新编号自动建档下发 |
| 录音结束 | `POST /api/open/ingest?durationMs=15000`，body 是 `.ogg`，头 `X-Device-Token` | 服务端按间隔归并成会话 |
| 全部传完 | `POST /api/open/ingest/close` | 立刻收尾，触发转写 + 纪要 |

本地文件名自带元信息，掉电也不会丢时长：`/spool/000012_8400_8200_1793510400.ogg`
（序号_编码时长ms_人声ms_录制起始epoch）。时长按 Ogg granule 精确算，是被 VAD 掐掉静音之后的真实长度。

### 时间戳：补传能还原真实时间线

最后那个 epoch 是这一片**开始录制的绝对时间**。上传时会转成 `recordedAt=2026-11-01T01%3A30%3A00Z` 一起发给服务端。

原因：服务端原先只看到达时间切会话。设备攒了一整天、回家一次性补传时，几十个分片几秒钟内全部到达，间隔都远小于 `gapSec`，
**一整天会被并成一条记录**（时间轴、纪要、日报全错）。带上 `recordedAt` 后，服务端改成按"本片录制开始 − 上一片录制结束"判断，
真实间隔 2 小时就会正确切成两条。

时间来源：

| 来源 | 说明 |
| --- | --- |
| PCF85063 RTC | 微雪 ePaper 板背面有这颗芯片 + 纽扣电池，断电继续走 |
| NVS 兜底 | 没有 RTC 的板子用上次保存的时间 + 开机时长推算，误差 = 关机时长 |
| 联网校准 | 每次真正连上 WiFi 都会对一次时（配对、补传、手动上传都算），用任意 HTTP 响应的 `Date` 头，偏差 > 2 秒就校准，不需要外网 NTP |

联网校准时如果发现时差超过 60 秒（典型是掉电丢时后离线录了一段），会把**还没上传的分片**的文件名里的 epoch 整体平移，补传时就是正确时间；已经上传的不受影响。`uploader_wifi_connect()` 连上后先对时，所以补传列目录时拿到的已经是校正后的时间。设备运行中每 10 分钟把时间落一次 NVS，掉电最多丢 10 分钟。

时间不可信时（比如第一次开机还没联过网），**不会传 `recordedAt`**，服务端自动退回按到达时间切——行为跟老固件一致，不会把数据搞坏。

不想每次按停就出纪要（比如一整天连续记、最后统一整理）：关掉 `RECALL_CLOSE_AFTER_UPLOAD`，改由服务端静默 180 秒自动收尾。

## 12. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 一直 `PAIR`，后台看不到设备 | WiFi 没连上（只支持 2.4G）、手机热点开了隔离、服务端地址填错；串口日志有 `连接 WiFi ...` |
| 手机搜不到 `Recall-XXXXXX` | 热点只在开机没凭据 / 连点 3 下时开，3 轮共 ~9 分钟后会自动关；按一下按键唤醒重来。串口有 `配网热点已开启` |
| 打开 `192.168.4.1` 转圈或白屏 | 手机同时开着移动数据，浏览器走了蜂窝；关掉数据或选「保持连接」。Android 提示"无互联网"属正常 |
| 配网保存后还是 `PAIR` | 密码错、连的是 5G 热点（同名的 5G 要选 2.4G 那个）、路由器开了 MAC 白名单；`PAIR` 页显示 `NO WIFI` 就是凭据没生效 |
| 一直 `PAIR` 但 WiFi 已连上 | 服务端地址填错 / 电脑防火墙挡了 8787 / 后台没点「添加设备」；串口 `服务端 http://...` 可以看出当前生效地址 |
| 服务器 IP 变了（换网 / DHCP 重分配） | 连点 3 下进配网，把「服务器地址」改成新 IP，不用重新烧 |
| 想换 WiFi / 搬家 | `READY` 时连点 3 下按键重新配网；彻底清空用 `idf.py erase-flash`（连 token 一起清） |
| 上传返回 401 | token 被换发或设备被删，固件会自动重新配对；一直 401 说明后台没绑定成功 |
| 录了但没声音 / VAD 不触发 | `MIC_SHIFT` 调小到 13；确认 L/R 接地（选左声道）；示波器看 WS 有无 16kHz 方波 |
| 声音爆音 | `MIC_SHIFT` 调到 15 |
| 屏幕全黑 | SSD1306 地址不是 0x3C；I2C 线反了 |
| TFT 反色 / 偏移 | `display.c` 里删掉 `tft_cmd(0x21)`，或改 `X_OFF/Y_OFF` |
| 录音只有 15 秒 | 不是 bug：每 15 秒落一个文件，掉电最多丢最后 15 秒。文件都在 `/spool` |
| 提示 `FLASH FULL` | 暂存区满了且老文件都不敢删（保护区），先联网把旧的传上去 |
| 电池掉得比预期快 | 板载 LDO 静态电流 + 麦克风没做电源开关；把 `RECALL_IDLE_SLEEP_S` 调小 |
