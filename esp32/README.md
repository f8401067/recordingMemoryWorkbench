# 忆录录音笔 · ESP32 固件

长按录音 → 人声检测 → Opus 压缩 → **先存本地 Flash** → 智能判断要不要传 → 上传服务端 → 自动转写 + 纪要。

配套服务端接口见项目根 `README.md` 的「硬件设备接入」一节，本固件就是那套协议的完整实现。

```
┌──────────────┐   I2S 16kHz    ┌──────────┐  20ms 帧   ┌────────┐
│ INMP441 数字麦│ ─────────────▶ │   VAD    │ ────────▶ │  Opus  │ 12kbps
└──────────────┘                └──────────┘  有人声才编 │ 编码器  │
                                                       └────┬───┘
                                                            │ Ogg 封装
                                      ┌─────────────────────▼──────────┐
                                      │  LittleFS /spool/*.ogg  (断电不丢) │
                                      └─────────────────────┬──────────┘
                                                      停止录音 │
                                    有效语音 ≥3s ? ──否──▶ 直接删除
                                            │是
                                            ▼
                              WiFi → POST /api/open/ingest → 转写
                                            │
                              POST /api/open/ingest/close → 纪要
```

## 1. C3 还是 S3

| | ESP32-C3 | ESP32-S3 |
| --- | --- | --- |
| 内核 | 单核 RISC-V 160MHz | 双核 XTensa LX7 240MHz |
| PSRAM | 无（400KB SRAM） | 常见 8MB Octal/Quad |
| 深睡电流（芯片手册） | 5µA | 7µA |
| 空闲（关 WiFi，80MHz） | ~15mA | ~25mA |
| 跑 12kbps Opus 的 CPU 占用 | ~25–30% / 160MHz | ~15% / 160MHz |
| 屏幕/外设余量 | GPIO 不够时很紧 | 富余，可上 TFT |
| 单价 | 最低 | 略高 |

**结论：当前只做 S3。C3 先放着，代码路径保留但不再作为验证重点。**

> ⚠️ **项目当前口径（2026-10）**：优先把 `esp32s3` 这条路走通、上真机、调参数。
> C3 的编译分支和分区表都还在（`idf.py set-target esp32c3` 仍能编过），
> 但不再跟着一起验证，等 S3 定型后再回头补。下文凡是标「C3」的内容都按**待启用**看待。

- S3：双核 LX7 240MHz + PSRAM，编码、VAD、LittleFS 写盘、HTTP 同时在跑也不喘；想加 TFT 屏、放大录音缓冲都随意。**本仓库默认 target 就是 `esp32s3`**，接线/调参/排错都以它为准。
- C3（待启用）：单核跑满也够（12kbps 下 Opus 约 25–30% CPU），但 RAM 只有 400KB，**别开 `RECALL_AUTO_SESSION` 之外的花哨功能**，也别指望上彩屏。深睡电流反而比 S3 更低，适合以后做极简款。

S3 固件已编译通过（见第 11 节）；C3 最后一次编译也通过，但之后的新改动不保证同步验证。

## 2. 省电：四个工作区

设备不是"一直录"，而是四档功耗来回切：

| 状态 | 触发 | 电流（估算） | 在干什么 |
| --- | --- | --- | --- |
| **深睡** | 待命闲置 5 分钟 | **10–60µA**（芯片 5–7µA + LDO 静态电流） | 只留按键唤醒，麦克风断电 |
| **待命** | 开机 / 唤醒后 | 12–18mA | 麦克风关，只轮询按键，屏幕 8Hz 刷新 |
| **录音** | 长按开始后 | 25–35mA | I2S 采样 + VAD + Opus + 写 Flash，WiFi 关闭 |
| **上传** | 录音结束且值得传 | 100–150mA（几秒） | WiFi 发射，传完立刻关射频 |

省电的六个具体手段，都在代码里：

1. **闲置即深睡**：`RECALL_IDLE_SLEEP_S`（默认 300 秒）后 `esp_deep_sleep_start()`，按键 `ext1`/GPIO 唤醒。按下去就醒，顺手接着算长按，不用按两次。
2. **麦克风可断电**：`PIN_MIC_PWR_EN` 接个 MOSFET，不开麦时麦克风彻底没电（INMP441 常开约 1.2mA，跟深睡电流比是数量级的差）。没接就是空操作。
3. **VAD 决定写不写**：没人在说话时**不进编码器、不写 Flash**。会议里 50%+ 时间是静音，这一条直接省掉一半 Flash 写入和一半文件体积。
4. **动态调频**：`esp_pm` 配 80–160MHz，平时 80MHz 跑，编码时自动拉满。
5. **射频按需开**：录完全程关着 WiFi，只有上传那几秒打开，连上后立刻 `WIFI_PS_MIN_MODEM`。
6. **少写 Flash**：每 15 秒落一个文件，不是每帧都 fsync；LittleFS 本身是掉电安全的。

### 为什么不用 light sleep

I2S 靠 APB 时钟采样，进 light sleep 时钟就停了，麦克风会断音。所以录音/待命期间**宁可 80MHz 空转也不睡**——真省电靠的是"没活干就深睡"，不是"半梦半醒"。

### 续航估算（1000mAh 电池）

| 用法 | 平均电流 | 续航 |
| --- | --- | --- |
| 连续录音（不放静音） | ~30mA | **约 33 小时** |
| 每天录 2 小时，其余深睡 | ~2.6mA | **约 16 天** |
| 只待机不录音（不深睡） | ~15mA | 约 66 小时 |
| 只待机（深睡） | ~50µA | 约 2 年（受电池自放电限制） |

> 电流是按数据手册 + 常见模块实测口径估的，不是这块板子的实测值。板载 LDO 的静态电流（常见 20–50µA）经常比芯片深睡电流还大，做低功耗选 LDO 时留意。

### 想再省一个数量级？

真正的"永远在线、0.1mA 级"需要 **S3 的 ULP-RISC-V 协处理器 + 模拟麦**：主核深睡，ULP 用 ADC 以 100Hz 采样能量，超过阈值才唤醒主核。本固件没做（C3 没有 ULP，写了两套代码维护成本高），但状态机已经把入口留好了——`RECALL_AUTO_SESSION` 打开后，"检测到人声就自动开录"的路径已经通了。

## 3. 接线

### ESP32-S3（默认 target）

| 模块 | 引脚 | ESP32-S3 |
| --- | --- | --- |
| INMP441 / ICS-43434 | VDD | 3V3 |
| | GND | GND |
| | L/R | GND（选左声道） |
| | SCK | GPIO4 |
| | WS | GPIO5 |
| | SD | GPIO6 |
| 按键（轻触） | 一端 | GPIO14 |
| | 另一端 | GND（内部上拉） |
| LED | 阳极串 1kΩ | GPIO15 |
| 蜂鸣器（无源） | + | GPIO16（建议过三极管） |
| SSD1306 OLED | SDA / SCL | GPIO8 / GPIO9（3V3、地址 0x3C） |
| ST7735 TFT 160x80 | SCLK / MOSI / CS / DC / RST | GPIO12 / 11 / 10 / 13 / 21 |

### ESP32-C3（4MB Flash 版，待启用）

| 模块 | 引脚 | ESP32-C3 |
| --- | --- | --- |
| INMP441 | SCK / WS / SD | GPIO4 / GPIO5 / GPIO6 |
| 按键 | | GPIO3 → GND |
| LED | | GPIO10 |
| 蜂鸣器 | | GPIO7 |
| SSD1306 | SDA / SCL | GPIO0 / GPIO1 |

注意事项：

- **麦克风一定接 3.3V**，接 5V 会烧。
- `GPIO2/8/9` 在 C3 上是 strapping 脚，别拿来接按键。
- 板载 LED 多数是低电平点亮，代码里 `LED_ACTIVE_LOW=1`；外接 LED 记得改成 0。
- 想要更省电：麦克风 VDD 串一个 P-MOS，栅极接 `PIN_MIC_PWR_EN`（S3 默认 GPIO7，改 `app_config.h` 即可）。

## 4. 编译与烧录

需要 ESP-IDF **v5.3 及以上**（本仓库用 v6.1 验证）。

```bash
cd esp32

# 1) 选芯片（当前只跟 S3，C3 先放着）
idf.py set-target esp32s3

# 2) 填服务器地址（出厂默认值）和可选的 WiFi
idf.py menuconfig
#   → 忆录录音笔 → 网络与账号：服务端地址 / 设备名
#        WiFi 可以留空，开机后用手机现场配网；服务端地址也能在配网页面上改（见第 5 节）
#   → 忆录录音笔 → 硬件：屏幕类型（无屏 / SSD1306 / ST7735）

# 3) 编译烧录
idf.py build
idf.py -p /dev/tty.usbmodem* flash monitor
```

分区表按 Flash 容量选（`sdkconfig.defaults.esp32c3` 里改）：

| Flash | 分区表文件 | 暂存区 | 能存多少纯语音 |
| --- | --- | --- | --- |
| 4MB | `partitions_4mb.csv` | 1.4MB | ~15 分钟 |
| 8MB | `partitions_8mb.csv`（默认） | 5MB | ~55 分钟 |
| 16MB | `partitions_16mb.csv` | 12MB | ~2.2 小时 |

> 12kbps 下 1 分钟约 90KB。会议里通常只有 40–50% 时间在说话，加上 VAD 跳过静音，实际能存的时长大约是上表的 2 倍。

## 5. 联网：设备怎么上网

只支持 **2.4GHz**（ESP32 没有 5G 射频）。WiFi 凭据和**服务端地址**都存在 NVS 里，优先级 **NVS > menuconfig**，换固件不会丢。

三种路子，按场景选：

### 方式一：编译期写死（自己用最省事）

```bash
idf.py menuconfig
#   忆录录音笔 → 网络与账号 → WiFi 名称 / WiFi 密码 / 服务端地址
```

烧一批同款设备、都是同一个 WiFi + 同一个服务器时这样最省事；缺点是换 WiFi 或换服务器要重新烧。

### 方式二：手机现场配网（推荐，送人 / 出厂默认）

NVS 里没有 WiFi 凭据时，设备开机自动进配网：

1. 手机 WiFi 列表里连 **`Recall-123456`**（后 6 位是设备编号，默认是开放热点）
2. 自动弹出或手动打开 **http://192.168.4.1**
3. 页面上有三项，一次配完：
   - **WiFi 名称**：自动扫描，列出 2.4G 热点 + 信号强度 + 🔒 标记，下拉选一个
   - **密码**：没有密码留空
   - **服务器地址**：自动填当前生效的值（`http://192.168.1.10:8787` 之类），改成电脑现在的局域网 IP 就行
4. 点「保存并重启」→ 设备把三项都写进 NVS → 自动 `esp_restart()`，下一次开机直接连网连服务器

无屏设备也能用：进配网时 LED 常亮 + 一声「嘀」，配网过程中网页上就能看到设备编号，不用听蜂鸣器念。

想给热点加密码（防隔壁邻居顺手改）：`menuconfig → 网络与账号 → 配网热点密码`，至少 8 位，留空即开放。

> 服务端地址会做基本校验（必须以 `http://` 或 `https://` 开头），结尾斜杠会自动去掉。
> 填错了不用慌：连不上就一直 `PAIR`，再连点 3 下进配网改回来就行，录音不会丢（都在 Flash 里）。

### 方式三：待命时连点 3 下重新配网

搬家 / 换路由器 / 改密码 / 换服务器 IP 时都不用重新烧固件：

> **`READY` 状态下 1.5 秒内连点 3 下按键** → 进配网热点，其余操作完全不变。

录音中不响应连点（避免手抖），只有 `READY` 和 `PAIR` 两个状态有效。

### 细节与边界

| 项 | 值 |
| --- | --- |
| 热点名 | `Recall-<设备编号>`，如 `Recall-903471` |
| 配网地址 | `http://192.168.4.1`（Android 可能提示"无互联网"，选「保持连接」） |
| 可配项 | WiFi 名称、WiFi 密码、服务端地址（三项一起存 NVS） |
| 界面接口 | `GET /`（页面）、`GET /cfg`（回填当前配置）、`GET /scan`（扫热点）、`POST /save` |
| 等待时长 | `RECALL_PROV_TIMEOUT_S`，默认 180 秒，超时自动关热点 |
| 没配 WiFi 会怎样 | 开 3 轮热点（约 9 分钟），之后进 `PAIR`，2 分钟没人管就深睡；按键唤醒会重新进配网 |
| 清空配置 | `idf.py erase-flash`（连 token 一起清），或在网页端删设备 |

`RECALL_SERVER_URL` 现在只是**出厂默认值**：全新设备 / 刚 erase 过的设备用它，一旦在配网页面上改过，就以 NVS 里的为准。

## 6. 使用流程

### 首次配对

1. 上电。如果还没配过 WiFi，会先进配网热点（见第 5 节），配完自动重启。
2. 有屏：屏幕显示 `PAIR` + 6 位编号；无屏：蜂鸣器逐位播报（0 用一声长音表示）。
3. 网页端「设置 → 硬件设备 → 添加设备」，输入这串数字。
4. 设备 3 秒内自动取回 token 并存入 NVS，蜂鸣器「嘀嘀嘀」表示成功，屏幕转 `READY`。

编号由 MAC 打散算出，永远不变；token 被换发或设备被删也不会卡死——上传时收到 401 会自动清 token 重新配对。

### 日常录音

| 操作 | 设备反应（有屏） | 设备反应（无屏） |
| --- | --- | --- |
| 长按 0.7 秒开始 | 屏幕 `REC` + 计时 + 电平条 | 两声短促「嘀嘀」，LED 慢闪 |
| 再长按一次结束 | 自动上传，显示 `SEND 1/3`、进度条 | 一声长「嘀——」，LED 快闪 |
| 上传成功 | `SENT` + 本次大小 | 三声「嘀嘀嘀」 |
| 没录到人声 | `SKIP / NO VOICE`（本地文件直接删） | 一声长低音后 LED 熄灭 |
| 出错 | `ERR` + 原因 | 一声很长的低音 |
| 待命时连点 3 下 | 进配网热点，屏幕 `CONNECT TO / RECALL-XXXXXX / 192.168.4.1` | LED 常亮 + 一声「嘀」 |

### 智能判断：传还是不传

- 一次录音里**真正有人说话**的累计时长 < `RECALL_MIN_VOICED_MS`（默认 3 秒）→ 判定"这次没录到东西"，本地文件删除，不联网。
- 够长 → 上传。上传成功立刻删本地文件；失败则**留在 Flash**，下次开机或 15 分钟后定时唤醒重试。
- 服务端按到达时间归并会话：间隔小于 90 秒的多次录音会自动合成一条记录（阈值可在后台按设备调）。

## 7. 屏幕：配网 / 配对 / 录音三块界面

`idf.py menuconfig → 硬件 → 屏幕类型` 四选一，界面代码完全共用（逻辑分辨率固定 128×64）：

- **自动（默认）**：上电后在 I2C 上探 0x3C / 0x3D，找到 SSD1306 就驱动，找不到就当无屏跑（LED + 蜂鸣器）。**接了 OLED 不用改配置**；接 SPI 的 ST7735 探不出来，要手动选。
- **无屏幕**：LED + 蜂鸣器。六种状态音上有区分（开始/结束/成功/出错），不看屏也知道成没成。
- **SSD1306 OLED 128×64（I2C）**：最便宜的方案，十几块钱。
- **ST7735 TFT 160×80（SPI）**：彩屏只用了黑白两色（省 RAM）。

三块关键界面（`python3 tools/preview_screen.py /tmp/s.png` 可以在不接屏的情况下生成预览图）：

```
WIFI                        PAIR               READY
──────────────────      ──────────────────  ──────────────────
    CONNECT TO              PAIR              HOLD 0.7S
 ┌──────────────┐        485412  (3×)        TO RECORD
 │ RECALL-485412│                             FREE 12000KB
 └──────────────┘       ADD IN WEB UI            PAIRED
    192.168.4.1
    2.4G ONLY
```

- **配网页**（没 WiFi 凭据时自动出现）：直接告诉你连哪个热点（`RECALL-485412`）、开哪个地址（`192.168.4.1`），并提示只支持 2.4G。
- **配对页**（WiFi 已连上、还没绑定）：3 倍字号显示 6 位设备编号，底下一行 `ADD IN WEB UI`——去网页端「设置 → 硬件设备 → 添加设备」输这个号即可。
- **待命页**：顶栏右侧一直挂着设备编号，中间提示长按录音，底部是剩余空间和绑定状态。

想换别的屏：在 `display.c` 里实现 `display_init` / `flush` / `display_power` 三个函数就行，画布、字库、排版都不用动。字体是 5×7 点阵，用 `tools/gen_font.py` 生成（改字形只需要改脚本里的 ASCII 画法）。

界面示例（录音中）：

```
REC                903471      ← 状态 + 配对编号
──────────────────────────
  ●   02:41                  ← 闪烁红点 + 大号计时
  ████ ███ ██ █              ← 20 格实时电平
HOLD TO STOP / V58S           ← 提示 + 已录人声
```

## 8. 音频方案

| 方案 | 码率 | 1 分钟 | 说明 |
| --- | --- | --- | --- |
| PCM/WAV 16kHz 16bit | 256kbps | 1.9MB | 原始，Flash 撑不住 |
| IMA-ADPCM | 64kbps | 480KB | 免依赖，但 4 倍于 Opus |
| **Opus 12kbps VOIP** | **12kbps** | **90KB** | 专为语音设计，识别准确率几乎无损 |

选 Opus 的理由：它是为**语音**设计的（SILK 层），12kbps 下的可懂度远超同码率的 MP3/AAC；服务端 ffmpeg 直接解，转写链路一行不用改。

链路细节：

- 采样 16kHz / 16bit / 单声道，I2S 一次读 20ms（320 采样）。
- VAD 判为静音就不进编码器——既省 Flash，也让识别更干净（没有大段静音）。
- 编码器：乐鑫官方 `esp_audio_codec` 的 OPUS，帧长 20ms，VOIP 模式，复杂度默认 2（C3 建议 1–2）。
- 封装：自己写的极简 Ogg 封装（`ogg_mux.c`，~180 行）。Ogg 页序号单调递增、CRC32 按 Ogg 规范（poly 0x04C11DB7）、granule 按 48kHz 计。
- 服务端：`Content-Type: audio/ogg` → 存盘 → ffmpeg 转 16k PCM → ASR → 纪要。

### 这个封装是验证过的

```bash
cd esp32/tools
ffmpeg -f lavfi -i "sine=frequency=440:duration=6" -ar 16000 -ac 1 \
       -c:a libopus -b:a 12k -frame_duration 20 /tmp/ref.ogg
python3 ogg_roundtrip.py /tmp/ref.ogg /tmp/pkts.bin     # 抽出真实 Opus 包
cc -O2 -I../main test_ogg_mux.c ../main/ogg_mux.c -o /tmp/test_ogg_mux
/tmp/test_ogg_mux /tmp/pkts.bin /tmp/mine.ogg           # 用固件同一份代码重封
ffprobe /tmp/mine.ogg                                   # duration=6.0265, codec=opus
```

用参考文件重新封装后，解码出的 PCM 与原件**相关系数 1.0000**（只多 216 个采样点，是尾部补帧）。

## 9. 和服务端的接口对照

| 时机 | 请求 | 用途 |
| --- | --- | --- |
| 未配对，每 3 秒 | `GET /api/open/pair?code=903471&name=...&firmware=1.0.0` | 后台一绑定就下发 token |
| 录音结束 | `POST /api/open/ingest?durationMs=15000`，body 是 `.ogg`，头 `X-Device-Token` | 服务端按间隔归并成会话 |
| 全部传完 | `POST /api/open/ingest/close` | 立刻收尾，触发转写 + 纪要 |

本地文件名自带元信息，掉电也不会丢时长：`/spool/000012_8400_8200.ogg`（序号_编码时长ms_人声ms）。时长按 Ogg granule 精确算，是被 VAD 掐掉静音之后的真实长度。

不想每次按停就出纪要（比如一整天连续记、最后统一整理）：关掉 `RECALL_CLOSE_AFTER_UPLOAD`，改由服务端静默 180 秒自动收尾。

**没有验证过的（说实话）：**

- ❌ 没有真板子，**电流是估算**，第 2 节的续航表按数据手册 + 常见模块口径推算。
- ❌ I2S 麦克风实际电平未实测，`MIC_SHIFT` 可能需要按你的麦克风微调。
- ❌ ST7735 的初始化序列按常见 160×80 模块写的，不同批次可能需要调反色（`0x21` 那行）或显示偏移（`X_OFF/Y_OFF`）。
- ❌ `RECALL_AUTO_SESSION`（无人按键自动开录）只做了逻辑，没在嘈杂环境实测误触发率。
- ❌ 配网热点（AP + httpd）只在编译和逻辑层面通过，没在真手机上验证过连热点 → 保存 → 重启这条链。

## 12. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 一直 `PAIR`，后台看不到设备 | WiFi 没连上（只支持 2.4G）、手机热点开了隔离、服务端地址填错；串口日志有 `连接 WiFi ...` |
| 手机搜不到 `Recall-XXXXXX` | 热点只在开机没凭据 / 连点 3 下时开，3 轮共 ~9 分钟后会自动关；按一下按键唤醒重来。串口有 `配网热点已开启` |
| 打开 `192.168.4.1` 转圈或白屏 | 手机同时开着移动数据，浏览器走了蜂窝；关掉数据或选「保持连接」。Android 提示"无互联网"属正常 |
| 配网保存后还是 `PAIR` | 密码错、连的是 5G 热点（同名的 5G 要选 2.4G 那个）、路由器开了 MAC 白名单；`PAIR` 页显示 `NO WIFI` 就是凭据没生效 |
| 一直 `PAIR` 但 WiFi 已连上 | 服务端地址填错 / 电脑防火墙挡了 8787 / 后台没点「添加设备」；串口 `服务端 http://...` 可以看出当前生效地址 |
| 服务器 IP 变了（换网 / DHCP 重分配） | 连点 3 下进配网，把「服务器地址」改成新 IP，不用重新烧 |
| 想换 WiFi / 搬家 | `READY` 时连点 3 下按键重新配网；彻底清空用 `idf.py erase-flash`（连 token 一起清） |
| 上传返回 401 | token 被换发或设备被删，固件会自动重新配对；一直 401 说明后台没绑定成功 |
| 录了但没声音 / VAD 不触发 | `MIC_SHIFT` 调小到 13；确认 L/R 接地（选左声道）；示波器看 WS 有无 16kHz 方波 |
| 声音爆音 | `MIC_SHIFT` 调到 15 |
| 屏幕全黑 | SSD1306 地址不是 0x3C；I2C 线反了 |
| TFT 反色 / 偏移 | `display.c` 里删掉 `tft_cmd(0x21)`，或改 `X_OFF/Y_OFF` |
| 录音只有 15 秒 | 不是 bug：每 15 秒落一个文件，掉电最多丢最后 15 秒。文件都在 `/spool` |
| 提示 `FLASH FULL` | 暂存区满了且老文件都不敢删（保护区），先联网把旧的传上去 |
| 电池掉得比预期快 | 板载 LDO 静态电流 + 麦克风没做电源开关；把 `RECALL_IDLE_SLEEP_S` 调小 |
